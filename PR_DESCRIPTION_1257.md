Harden concurrent execution around src/app/sitemap.ts
Closes #1257

Description
Hardens src/app/sitemap.ts so concurrent or repeated execution cannot produce stale, unsafe, inconsistent, or unserialisable output.

Next.js calls the default export once per GET /sitemap.xml in development, once per build worker in production, and hands the result to its XML serialiser. Seven defects let repeated or concurrent execution break that contract. Each was reproduced with a probe test against the previous module before being fixed, and each now has a regression test that fails against it (25 of the new tests fail against the old module; 84/84 pass against the new one).

Defects fixed
Timestamp aliasing (stale/inconsistent across calls). Every entry — and the injected clock — shared one mutable Date. A consumer mutating one entry rewrote every entry, the clock itself, and every document built afterwards (reproduced: the next document was stamped 1970-01-01). Fix: resolveLastModifiedMs() returns a primitive millisecond value; buildEntries() mints a distinct Date per entry (new invariant S8).
S2 "never throws" violated by a throwing reporter. buildSitemap() propagated the sink's exception → route 500. Fix: guardReporter() contains it; a fixed note goes to console.error outside production without echoing the report payload.
S2 violated by a throwing clock. now() was called unguarded. Fix: guarded; treated exactly like an invalid clock (reported, replaced, never propagated).
Invalid Date in output. When the process clock itself was broken, the old new Date() fallback was the same broken clock, so entries carried Invalid Date and Next's serialiser threw RangeError: Invalid time value → 500 (reproduced). Fix: a finite-millisecond fallback chain SOURCE_DATE_EPOCH → injected clock → Date.now() → epoch 0; every rung must be finite, so the document is always serialisable.
Dedupe-key collision (S6 violation). source was missing from the once-per-condition key, so the two SITEMAP_INVALID_TIMESTAMP conditions (bad epoch vs broken clock) produced identical signatures and the second was silently swallowed (reproduced). Fix: key = context|code|reason|source|sanitised.
Report memo bounded only by convention + per-request closure churn. sitemap() allocated a fresh dedupe closure per request and the module-level Set had no hard cap. Fix: createSitemapReportMemo() — one frozen instance per process, hard-capped at SITEMAP_MAX_REPORTED_CONDITIONS (64) with oldest-first eviction, mark-before-delivery so a throwing sink is not retried per request, injectable maxEntries so the bound is testable. Mirrors the createSiteUrlResolver pattern accepted for robots.ts in #1252/PR #1398.
Non-string routes silently became the home entry. null/42 in a route list emitted the base URL instead of being rejected. Fix: dropped and reported with the typeof name only (never the value).

Invariants added/strengthened (documented in the module header)
S2 (strengthened): never throws AND the document is always serialisable; reporter, clock, resolver and console failures are contained.
S6 (strengthened): dedupe key covers every discriminating field, so distinct conditions can never swallow each other.
S7 (strengthened): one frozen memo per process, hard-capped with oldest-first eviction — bounded by construction, not convention.
S8 (new): isolation across invocations — fresh array, fresh entry objects, distinct Date per entry; nothing aliases the clock, SITEMAP_ROUTES, or another document. Output is deliberately not frozen (Next's serialiser owns the result); isolation is provided by exclusive ownership.
S9 (new): one input snapshot per document — NEXT_PUBLIC_SITE_URL and SOURCE_DATE_EPOCH are read exactly once at entry, the clock is invoked at most once, the build is fully synchronous, and there is no cache to go stale, so a changed environment is honoured by the very next call and no document can mix two configurations.

Security & failure-mode notes
No authentication, authorization, wallet logic, network or storage access is involved; the route is pure computation over configuration.
Reports/logs never echo the configured URL, route values, credentials or sink internals — only stable codes, fixed reason vocabularies, typeof names and character-class descriptions.
Worst-case failure modes now degrade instead of breaking: broken sink → silent containment + fixed dev note; broken clock → finite fallback stamp; hostile resolver output → per-route drop with re-validation; log-flood → once-per-condition, hard-capped memo; mutation by a consumer → exclusively owned per-call documents.
